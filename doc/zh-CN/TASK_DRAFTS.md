# 项目管理和任务草案

**所有项目**页面显示注册的文件夹、发布的数量
任务和最新活动。活动考虑了任务、历史记录和
费用记录。铅笔按钮允许您重命名项目或选择
系统对话框中的现有文件夹。更改路径会更新注册和标记；
保存项目 ID、工作人员、任务和设置，但不移动文件。
无法选择已注册到其他项目的文件夹。

## 全局设置

从项目选择页面或选项卡打开**全局设置**
**全局设置**在任何板的设置中。这些参数对于所有项目都是通用的
1 个 AgentBoard 基础：

- 默认情况下，每**10 秒**启用定时器自动保存草稿。
- **离开现场时保存**默认启用，并且可以单独配置。
- **MCP 项目上下文** 检查全局启用和禁用。他们的面积
  操作和单独的 CLI 标志在 [Workers 和 MCP](WORKERS_MCP.md).

## 草稿生命周期

“新建任务”对话框将未完成的工作保存为草稿。状态行
区分未保存的更改、正在进行保存、保存的草稿和错误
保护。该草案不会出现在董事会上，并且 MCP 工作人员无法使用该草案，直到
发表。

发布之前，使用**创建任务**按钮填写**标题、状态、
负责人和描述**。在此之前，**保存草稿**保存草稿而不创建
任务。关闭时默认丢弃空表单。如果清除
现有草稿为空状态，下次保存时将被删除。
关闭非空对话框也会保存它。

板上的 **草稿** 按钮允许您继续或删除已保存的草稿。
支持多个草稿。重启后，打开
草稿。草稿存储在SQLite中；每次更改时，本地的都会更新
在浏览器中复制，因此未保存的编辑可以在重新启动后保留下来或
临时服务器故障。如果浏览器存储不可用，则会出现一个警告对话框
关闭之前必须将草稿保存在服务器上。

撰写草稿时使用修订来防止一个窗口覆盖工作
另一个。如果服务器上已有一个，则丢失的保存响应是一致的
相同的数据。如果内容不同，则显示冲突，
**恢复为新草稿**单独保存本地内容。出版物
原子性和幂等性：在丢失后重新发布相同的草稿
响应返回相同的任务而不是创建副本。
