# Управление проектами и черновики задач

Страница **All projects** показывает зарегистрированную папку, число опубликованных
задач и последнюю активность. Активность учитывает изменения задач, истории и
записей расхода. Кнопка с карандашом позволяет переименовать проект или выбрать
существующую папку в системном диалоге. Смена пути обновляет регистрацию и маркер;
ID проекта, воркеры, задачи и настройки сохраняются, файлы не перемещаются.
Папки, уже зарегистрированные за другим проектом, выбрать нельзя.

## Глобальные настройки

Откройте **Global settings** со страницы выбора проекта или на вкладке
**Global settings** в настройках любой доски. Эти параметры общие для всех проектов
одной базы AgentBoard:

- Автосохранение черновиков по таймеру включено по умолчанию, каждые **10 секунд**.
- **Сохранение при выходе из поля** включено по умолчанию и настраивается отдельно.
- Проверки **MCP project context** включаются и выключаются глобально. Их область
  действия и отдельный флаг CLI описаны в разделе [Воркеры и MCP](WORKERS_MCP.md).

## Жизненный цикл черновика

Диалог новой задачи сохраняет незавершённую работу как черновик. Строка статуса
различает несохранённые изменения, идущее сохранение, сохранённый черновик и ошибку
сохранения. Черновик не появляется на доске и недоступен MCP-воркерам, пока не
опубликован.

Перед публикацией кнопкой **Create task** нужно заполнить **Title, State,
Responsible и Description**. До этого **Save draft** сохраняет черновик без создания
задачи. Пустая форма по умолчанию при закрытии отбрасывается. Если очистить
существующий черновик до пустого состояния, он удаляется при следующем сохранении.
Закрытие непустого диалога тоже сохраняет его.

Кнопка **Drafts** на доске позволяет продолжить или удалить сохранённые черновики.
Поддерживается несколько черновиков. После перезагрузки восстанавливается открытый
черновик. Черновики хранятся в SQLite; при каждом изменении обновляется локальная
копия в браузере, поэтому несохранённые правки переживают перезагрузку или
временный сбой сервера. Если хранилище браузера недоступно, диалог предупреждает,
что черновик на сервере нужно сохранить перед закрытием.

Запись черновиков использует ревизии, чтобы одно окно не перезаписало работу
другого. Потерянный ответ на сохранение согласуется, если на сервере уже есть
идентичные данные. Если содержимое отличается, показывается конфликт, а
**Recover as a new draft** сохраняет локальное содержимое отдельно. Публикация
атомарна и идемпотентна: повтор публикации того же черновика после потерянного
ответа возвращает ту же задачу, а не создаёт копию.
