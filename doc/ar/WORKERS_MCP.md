# اتصال العمال وMCP

## الخطوة 1. أنشئ عاملاً

في AgentBoard، افتح **العمال ← إضافة عامل**. حدد ملف تعريف العميل: Codex، أو Claude Code، أو Gemini CLI، أو Cursor، أو OpenCode، أو Ollama عبر OpenCode، أو VS Code Copilot أو عميل MCP آخر. يملأ الملف التعريفي الميزات النموذجية (الكود، والاختبارات، وGit)؛ يمكنك تغييرها. الاسم مرئي على اللوحة، و`Slug` هو معرف قصير بدون مسافات لأمر MCP. انقر **حفظ**.

عامل واحد يتوافق مع شخصية واحدة من الذكاء الاصطناعي. إنشاء عمال مختلفين لعملاء أو فرق مختلفة. يصف ملف تعريف القدرة التخصص، ولكنه لا يوسع حقوق الذكاء الاصطناعي لتشمل مراحل المهمة.

## الخطوة 2. انسخ التكوين

افتح العامل الذي تم إنشاؤه. تعرض كتلة **تشخيصات MCP** جزء التكوين والملف الذي تريد إضافته. انقر **نسخ تكوين MCP**. إذا كان الملف موجودًا بالفعل، أضف الخادم المقترح إلى كائن `mcpServers`/`servers`/`mcp` الموجود دون مسح الخوادم الأخرى.

يبدو الأمر الرئيسي كما يلي:

```text
agentboard mcp --worker codex
```

`--worker` — `Slug` للعامل الذي تم إنشاؤه. يقوم عميل MCP بتشغيل هذا الأمر بنفسه عندما يحتاج إلى أدوات.

### يعمل MCP بدون واجهة ويب

`agentboard mcp` هي عملية stdio منفصلة تقوم بحد ذاتها بفتح قاعدة بيانات AgentBoard. لا يحتاج إلى `agentboard open`/`serve`، ولا يعتمد على المجلد الذي يتم تشغيل واجهة الويب منه، وعلى عدد مثيلات واجهة الويب التي يتم تشغيلها. يمكن تشغيل العديد من الوكلاء في وقت واحد، كل منهم في مشروعه الخاص: يقوم كل عميل بتشغيل عملية MCP الخاصة به، ويستخدمون جميعًا نفس قاعدة بيانات SQLite بشكل آمن.

### كيفية اختيار المشروع

يعمل خادم MCP في أي مجلد. في المرة الأولى التي تستدعي فيها الأداة، تكون مرتبطة بالمشروع:

1. `--project PATH`، إذا تم تحديده (أي مجلد داخل المشروع المسجل مناسب)؛
2. وإلا فإن مجلدات العمل (الجذور) الخاصة بالعميل، إذا أبلغ عنها العميل؛
3. وإلا فإن المجلد الذي قام العميل بتشغيل خادم MCP فيه.

يقوم `get_my_board` بإرجاع المشروع والعامل المحدد إلى `session` مع `binding_source`. إذا تغيرت مجلدات العمل الخاصة بالعميل، فإن الاستدعاء التالي للأداة يؤدي إلى الربط مرة أخرى. بدون `--worker`، يتم استخدام العامل الممكّن الوحيد للمشروع.

إذا لم يكن الربط ممكنًا، تقوم كل أداة بإرجاع خطأ يجب على الوكيل تمريره إلى المستخدم؛ لا تتم قراءة بيانات المهمة في هذه الحالة:

| الكود | معنى |
| --- | --- |
| `NO_PROJECTS` | لا توجد مشاريع في قاعدة البيانات. قم بتنفيذ `agentboard init` في مجلد المشروع وقم بإنشاء عامل. لا حاجة لإعادة التشغيل. |
| `PROJECT_REQUIRED` | مجلد العمل خارج المشاريع المسجلة. تسرد الرسالة المشاريع. |
| `PROJECT_NOT_FOUND` | `--project` ليس داخل مشروع مسجل. |
| `PROJECT_AMBIGUOUS` | تمتد مجلدات عمل العميل إلى مشاريع متعددة. إضافة `--project`. |
| `NO_WORKERS`، `WORKER_REQUIRED`، `WORKER_NOT_FOUND`، `WORKER_DISABLED` | قم بإنشاء عامل أو تمكينه أو تحديده عبر `--worker`. |

تكوينات **Codex** و**Gemini CLI** مخصصة ومشتركة عبر جميع المجلدات، لذلك لا تحتوي على `--project`: أنشئ عاملًا بنفس السلسلة الثابتة في كل مشروع يتم تشغيل هذا العميل فيه. تحتوي الملفات على مستوى المشروع (Claude Code، Cursor، OpenCode، VS Code) على `--project` لمشروعهم.

### التصميم الصريح والتحقق من السياق

إذا تم تحديد `--project` وكان مجلد بدء التشغيل أو مجلد العمل الخاص بالعميل موجودًا في مشروع مختلف، فستطلب الأدوات التأكيد عبر استنباط MCP. يتلقى العملاء الذين ليس لديهم استنباط النموذج `PROJECT_CONTEXT_MISMATCH` قبل الوصول إلى المهام. قم بتصحيح التكوين أو إزالة `--project` للاكتشاف التلقائي أو التأكيد بشكل صريح على أنك تنوي العمل مع مشروع آخر باستخدام علامة `--allow-project-mismatch`. يؤدي تغيير مجلدات العمل إلى إعادة تعيين التأكيدات السابقة. المشاريع المحددة تلقائيًا لا تتطلب تأكيدًا.

**الإعدادات العامة → سياق مشروع MCP** تتحكم في عمليات التحقق هذه لجميع المشاريع والعاملين في نفس قاعدة البيانات. ممكّن افتراضيًا. في حالة التعطيل، يستخدم MCP المشروع المحدد دون تأكيدات أو أخطاء عدم تطابق. تطبق الجلسات المفتوحة بالفعل الإعداد في المرة التالية التي يتم فيها استدعاء الأداة؛ ويستمر اتباع قواعد رؤية المهام والانتقالات والاختبار البشري.

بعد التحقق، تعرض الكتلة التشخيصية المسار المطلق إلى `agentboard.exe` قيد التشغيل. إنه مفيد بشكل خاص عند التثبيت من ملف ZIP. عند التثبيت عبر Scoop، يمكنك استخدام الأمر `agentboard` إذا رأى العميل نفس `PATH`.

## الخطوة 3: أضف خادمًا إلى عميلك

تحتوي واجهة العامل بالفعل على جزء جاهز. وفيما يلي شرح لمكان استخدامه:

| العميل | مكان الإدراج | كيفية التحقق من جانب العميل |
| --- | --- | --- |
| الدستور الغذائي | `%USERPROFILE%\.codex\config.toml`، قسم `[mcp_servers.agentboard_<slug>]` | `codex mcp list` |
| كلود كود | `.mcp.json` في مجلد المشروع | `claude mcp list` |
| الجوزاء CLI | `%USERPROFILE%\.gemini\settings.json`، الكائن `mcpServers` | `/mcp list` في الجوزاء CLI |
| المؤشر | مشروع `.cursor\mcp.json` | قائمة خوادم MCP في إعدادات المؤشر |
| الكود المفتوح | مشروع `opencode.json`، الكائن `mcp` | قائمة أدوات MCP في OpenCode |
| مساعد الطيار VS Code | مشروع `.vscode\mcp.json`، الكائن `servers` | الأمر **MCP: خوادم القائمة** |

أمثلة على Codex (تكوين المستخدم، اكتشاف المشروع تلقائيًا) وClaude Code (ملف المشروع) مع المشروع `C:\Projects\MyFirstProject` والعامل `codex`:

```toml
# %USERPROFILE%\.codex\config.toml
[mcp_servers.agentboard_codex]
command = "agentboard"
args = ["mcp", "--worker", "codex"]
```

```json
{
  "mcpServers": {
    "agentboard_codex": {
      "type": "stdio",
      "command": "agentboard",
      "args": ["mcp", "--project", "C:\\Projects\\MyFirstProject", "--worker", "codex"]
    }
  }
}
```

في JSON، يتم مضاعفة الخط المائل العكسي لنظام التشغيل Windows؛ يقوم جزء جاهز من الواجهة بذلك تلقائيًا. تحتوي التكوينات التي تم إنشاؤها على `--db` الفعلي لخادم الويب، لذلك يستخدم HTTP وMCP نفس القاعدة، حتى لو كانت بيئة العميل مختلفة.

**Ollama** يوفر نموذجًا محليًا، لكنه لا يحل محل عميل MCP. يقوم ملف تعريف **Ollama via OpenCode** بإنشاء تكوين MCP لـ OpenCode؛ قم بتكوين OpenCode بشكل منفصل على نموذج Ollama. يعد عميل آخر متوافق مع MCP مع Ollama مناسبًا أيضًا.

## الخطوة 4: التحقق من اتصالك

1. افتح بطاقة العامل وانقر فوق **التحقق مرة أخرى**. **التحقق من الخادم** يقوم بتشغيل برنامج stdio حقيقي قابل للتنفيذ مع هذا المشروع والعامل والقاعدة، ويتحقق من المصافحة وقائمة الأدوات وتحديد موقع المشروع والعامل.
2. قم بتشغيل أو إعادة تشغيل عميل AI بعد إضافة ملف التكوين. اطلب منه الاتصال بـ `get_my_board`.
3. سيظهر **العميل المتصل** في AgentBoard وستظهر جلسة جديدة في القائمة. هذا فقط يؤكد اتصال عميلك. إذا كانت هناك أدوات، ولكن العميل غير متصل، فتحقق من المسار إلى البرنامج واسم ملف التكوين وبناء جملة JSON/TOML الخاص به.

ابدأ جلسة عملك مع `get_my_board`. لا يتلقى الذكاء الاصطناعي المهام من `Backlog` و`Complete`، حتى لو كان يعرف هويتهم. لا يمكن للذكاء الاصطناعي أن يتظاهر بأنه إنسان وليس لديه أمر عام "بالتحرك إلى أي مكان". يعتمد العمل مع نظام الملفات خارج AgentBoard على إمكانيات العميل المحدد ووضع الحماية الخاص به.

تعلن كل أداة عن `title` وجميع تلميحات سلوك MCP الأربعة (`readOnlyHint`، `destructiveHint`، `idempotentHint`، `openWorldHint`) كقيم منطقية صريحة. أدوات القراءة للقراءة فقط وعاجزة. تقوم أدوات التسجيل فقط بإضافة السجلات أو نقل المهام إلى الأمام، لذلك لا يوجد أي منها مزعج أو يتجاوز قاعدة AgentBoard المحلية.
