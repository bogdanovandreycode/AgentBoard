AgentBoard 0.4.0 makes MCP workers independent of the web UI and of the folder it was started from, and adds task drafts and project management.

## MCP workers

- `agentboard mcp` starts in any folder and no longer requires `agentboard open` or `serve`. Several agents can work on different projects at the same time, regardless of how many web UI instances are running.
- The project is selected on the first tool call: `--project`, then the client's workspace roots, then the MCP launch folder. A workspace change rebinds the session. `--worker` is optional when a project has a single enabled worker.
- Configuration problems are returned as tool errors that tell the agent to inform the user: `NO_PROJECTS`, `PROJECT_REQUIRED`, `PROJECT_NOT_FOUND`, `PROJECT_AMBIGUOUS`, `NO_WORKERS`, `WORKER_REQUIRED`, `WORKER_NOT_FOUND` and `WORKER_DISABLED`. After `agentboard init`, the agent can retry without restarting the MCP server.
- `get_my_board` now returns the bound project and worker (`session`), the task summaries (`board`) and a suggested `next_step`.
- Every tool declares a `title` and explicit `readOnlyHint`, `destructiveHint`, `idempotentHint` and `openWorldHint` annotations, as required by MCP directories.
- Generated Codex and Gemini CLI configurations are user-level and no longer pin one project. Project-level configurations keep `--project`.
- The worker **Server check** also verifies that the configured project and worker resolve.

## Projects, drafts and settings

- Recoverable task drafts with configurable autosave and save on blur.
- Project statistics, renaming and folder changes with the native Windows folder dialog.
- Global settings shared by all projects, including the MCP project-context check toggle.

## Reliability

- The SQLite database uses WAL mode, a longer lock timeout and immediate write transactions, so web servers and many MCP processes can share it safely.
- `agentboard open`/`serve` fall back to a free local port when the default port is used by another program.
- The documentation site falls back to English for untranslated pages instead of failing to build; all pages are translated again.

## Upgrading

- Restart AgentBoard and reconnect MCP clients after upgrading. The database is migrated to WAL mode automatically; back up `agentboard.db` together with its `-wal` file while AgentBoard is running.
- Agents that parsed the old `get_my_board` object should read task groups from its `board` field.
