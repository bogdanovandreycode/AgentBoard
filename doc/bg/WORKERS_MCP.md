# Работници и MCP връзка

## Стъпка 1. Създайте работник

В AgentBoard отворете **Работници → Добавяне на работник**. Изберете клиентски профил: Codex, Claude Code, Gemini CLI, Cursor, OpenCode, Ollama чрез OpenCode, VS Code Copilot или друг MCP клиент. Профилът попълва типични характеристики (код, тестове, Git); можете да ги промените. Името се вижда на платката, а `Slug` е кратък идентификатор без интервали за MCP командата. Щракнете върху **Запазване**.

Един работник отговаря на една личност на ИИ. Създайте различни работници за различни клиенти или екипи. Профилът на възможностите описва специализацията, но не разширява правата на AI върху етапите на задачата.

## Стъпка 2. Копирайте конфигурацията

Отворете създадения работник. Блокът **MCP диагностика** показва конфигурационния фрагмент и файла, където да го добавите. Щракнете върху **Копиране на MCP конфигурация**. Ако файлът вече съществува, добавете предложения сървър към съществуващия обект `mcpServers`/`servers`/`mcp`, без да изтривате другите сървъри.

Основната команда изглежда така:

```text
agentboard mcp --project C:\Projects\MyFirstProject --worker codex
```

`--project` трябва да сочи към папката, която сте регистрирали чрез `agentboard init`. `--worker` — `Slug` на създадения работник. MCP клиентът сам изпълнява тази команда, когато има нужда от инструменти. В браузъра AgentBoard уеб сървърът може да работи отделно.

След проверка диагностичният блок показва абсолютния път до работещия `agentboard.exe`. Това е особено полезно при инсталиране от ZIP. Когато инсталирате чрез Scoop, можете да използвате командата `agentboard`, ако клиентът вижда същия `PATH`.

## Стъпка 3: Добавете сървър към вашия клиент

Работният интерфейс вече има готов фрагмент. По-долу е обяснение къде се използва:

| Клиент | Къде да вмъкна | Как да проверя от страна на клиента |
| --- | --- | --- |
| Кодекс | `%USERPROFILE%\.codex\config.toml`, раздел `[mcp_servers.agentboard_<slug>]` | `codex mcp list` |
| Клод Код | `.mcp.json` в папката на проекта | `claude mcp list` |
| Gemini CLI | `%USERPROFILE%\.gemini\settings.json`, обект `mcpServers` | `/mcp list` в Gemini CLI |
| Курсор | Проект `.cursor\mcp.json` | списък с MCP сървъри в настройките на курсора |
| OpenCode | Проект `opencode.json`, обект `mcp` | списък на MCP инструменти в OpenCode |
| VS Code Copilot | Проект `.vscode\mcp.json`, обект `servers` | команда **MCP: Списък на сървърите** |

За Codex и Claude Code, пример с проекта `C:\Projects\MyFirstProject` и работника `codex`:

```toml
# %USERPROFILE%\.codex\config.toml
[mcp_servers.agentboard_codex]
command = "agentboard"
args = ["mcp", "--project", "C:\\Projects\\MyFirstProject", "--worker", "codex"]
```

```json
{
  "mcpServers": {
    "agentboard_codex": {
      "type": "stdio",
      "command": "agentboard",
      "args": ["mcp", "--project", "C:\\Projects\\MyFirstProject", "--worker", "codex"]
    }
  }
}
```

В JSON обратната наклонена черта на Windows се удвоява; готов фрагмент от интерфейса прави това автоматично. Ако използвате `--db` с персонализирана база, добавете го към `args` MCP конфигурация и посочете същия път, както при стартиране на `open`.

**Ollama** предоставя локален модел, но не замества MCP клиента. Профилът **Ollama чрез OpenCode** генерира MCP конфигурация за OpenCode; отделно конфигурирайте OpenCode на модела Ollama. Друг MCP-съвместим клиент с Ollama също е подходящ.

## Стъпка 4: Проверете връзката си

1. Отворете картата на работника и щракнете върху **Провери отново**. **Проверката на сървъра** трябва да показва броя на MCP инструментите. Това е вътрешна проверка на протокола и откриване на сървърни инструменти.
2. Стартирайте или рестартирайте AI клиента след добавяне на конфигурационния файл. Помолете го да се обади на `get_my_board`.
3. **Свързан клиент** ще се появи в AgentBoard и нова сесия ще се появи в списъка. Само това потвърждава връзката на вашия клиент. Ако има инструменти, но клиентът не е свързан, проверете пътя до програмата, името на конфигурационния файл и неговия JSON/TOML синтаксис.

Започнете работната си сесия с `get_my_board`. AI не получава задачи от `Backlog` и `Complete`, дори ако знае техния ID. AI не може да се преструва на човек и няма обща команда „премести се където и да е“. Работата с файловата система извън AgentBoard зависи от възможностите и пясъчника на избрания клиент.

Официални инструкции за клиенти: [Codex](https://developers.openai.com/learn/docs-mcp), [Claude Code](https://docs.anthropic.com/en/docs/claude-code/mcp), [Gemini CLI](https://geminicli.com/docs/tools/mcp-server/), [Cursor](https://prod.cursor.com/docs/cli/mcp), [OpenCode](https://opencode.ai/docs/mcp-servers/), [VS Code](https://code.visualstudio.com/docs/agent-customization/mcp-servers).
